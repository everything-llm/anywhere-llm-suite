# browser-lean

Tasks on the web, as one AnythingLLM agent skill: research (search the web, look at a page) and a real Chrome with a tab per chat, which the agent opens, reads as text with a ref on each element, and acts on by those refs. It runs inside AnythingLLM's process, with the Puppeteer bundled in the skill and the Chrome AnythingLLM's image ships, so nothing is installed beside it. A task worth running again, and any API with a key, are the library skill's; the browser is for what only a person's clicks can do.

| Action | Does |
| --- | --- |
| `guide` | how to pick the way to do a task, by topic (`static/guide/`) |
| `search` | the web, through `SEARCH_URL` (DuckDuckGo's plain HTML search by default) |
| `look` | reads a page in a page of its own, without moving the tab |
| `open` | an address in this chat's tab |
| `read` | the tab as text, with refs (`find`, `from` for long pages) |
| `act` | click, fill, type, press, select... by ref; or several `steps` |
| `login` | types the saved login; with none, the user enters it on the tab's page; `confirm_ref` asks them to choose a new account's password; `what` asks them for a code the same way |
| `call` | one request from the tab, with its signed-in session (`auth` "session") |

Each answer about the tab ends with its card, a picture of the tab that opens its page. There the user sees the tab, enters what the agent asks for (sealed on their device; the model never sees it) and saves the login they typed. The saved logins and passkeys are listed and deleted on the Vault, which the tab's page links to: a page this skill serves, with its logins section, and the library skill too, with its keys and sign-ins, so either works alone. A saved password is put into the page only in one call that first checks the field is in the page's own document on the login's site, never in a frame and never as keystrokes; a code is typed after the same check. Every request Chrome makes goes through the fence: the public web only, the hosts in `FENCE_ALLOW`, and the origins (scheme, host and port) the user lets through on the Vault, under Allowed addresses (`#shared/addresses`). An address the fence refuses is refused at once, and the agent is told the user can let it through there; the Vault lists the ones refused lately, to allow with a tap.

## Where it keeps things

| What | Where |
| --- | --- |
| Logins and passkeys | `vault-lean/vault.json` in AnythingLLM's storage, encrypted, shared with the library |
| Each workspace's cookies (so its sign-ins last) | `vault-lean/sealed/session-<workspace>.json`, encrypted with the vault's key |
| Chrome's profile while it runs | a temporary folder, removed when it closes |
| Each workspace's tabs' page names | `browser-lean/<workspace>/` |
| The tabs' pictures, state and pages | `public/browser-lean/` beside AnythingLLM's server |
| Your own versions of the guide and the page | `browser-lean/static/`, at the same paths as `static/` |

## Using it

`anywherellm-suite install` puts it in, or import it from AnythingLLM's Community Hub. Switch on Browser under Agent Skills, and set its ANYTHINGLLM_URL to the address you open AnythingLLM at, so the card opens anywhere. It needs a Chrome: the newest one Puppeteer downloaded (`PUPPETEER_CACHE_DIR`, else `~/.cache/puppeteer`, where AnythingLLM's Docker image keeps its collector's), else a system Chrome or Chromium in `/usr/bin`; set `BROWSER_LEAN_CHROME` in AnythingLLM's environment to choose one. The tab's page needs the pages' key: make it once in Settings > Browser Extension and paste it into `PAGE_KEY` here or in any suite skill ([the setup guide's step 1](https://everything-llm.github.io/anywhere-llm-suite/setup.html#page-key)). It has no key slot: it asks for no API keys, and a login or a code is typed on the tab's page.

The tab's page is drawn as the Browser Lean Design canvas has it: the page fills the screen, and one bar at the bottom, in thumb reach, holds Back; the address pill, with a lock (or not) and the site's host (cut at its start, so the site's own name stays in view), which opens a new tab's home when tapped, and at its end the holder chip, never hidden: Agent while the agent has a chat's tab (tap it to take the tab over), You while the user holds it (tap it to hand it back), and on a tab of the user's own a You that does nothing; the tab count, which opens the workspace's tabs as a sheet (each chat's, a green dot and "The agent is using it" on the ones the agent is using, then the user's own, and New tab); and More (Forward, Reload, Logins, the Vault on its Logins tab, New tab, Close this tab). Scrolling the page down shrinks the bar to a thin line with the host and the chip, both still tappable; scrolling up or tapping the host brings it back, and with reduced motion it changes without animating. At 200% text the bar wraps, the host alone cut short. The page draws no Close of its own: AnywhereLLM Lite opens it in a Custom Tab, whose toolbar shows the tab's title and a Close, and in a browser tab the browser's Back does it. A request for a login or a code rises as a card above the bar, which stays thin under it, so Back and More are out of reach until it's answered; its save switch starts off, and tapping the page above it (or the Agent chip) takes the tab over instead. The agent's card then reads "Sign in · <the page's title>". A user name typed there stays on the device until the request is answered, turned down or ended, so a reload while you look the password up loses nothing; the password and the code are never kept (nor what is typed into a field of the page itself). An offer to save a login or a passkey rises the same way, the chip reading You and off until it's answered.

On a chat's tab opened inside AnywhereLLM (whose web view gives the page its `AnywhereLLMApps` channel, as Apps' Comment has it), a "Message the agent" composer sits above the bar, shrinking away with it: Point (a crosshair), the field and Send, off while it's empty. Tapping into the field makes it the multi-line composer above the keyboard, over the thin bar. Point makes taps pick instead of press, up to 5, without taking the tab over: each is the element in view the agent's `read` names by its ref (the state's `targets`), shown as a numbered outline on the picture and a numbered chip ("1 · button “Sign in”"), removable with its ×; a password field can't be picked, and Done or Esc ends it. Send puts the message in the chat the tab belongs to (its AnythingLLM thread, by its slug, read from AnythingLLM's thread model; a chat through the developer API has none, and AnywhereLLM sends to the chat it has open) as the user's own, naming the page, then each pick by its ref, kind and name, then the words; then "Sent to <chat>" with Open chat. The composer is the one Apps' Comment uses (`packages/shared/composer.js`), and [docs/browser-tab.md](../../../docs/browser-tab.md) has the channel's messages. A page opened anywhere else, and the user's own tabs and a new tab's home, have no chat bar.

On the tab's page the user can take the tab over: tap the page (or the Agent chip, Back, or Forward or Reload in More), swipe to scroll, type into a field with their own keyboard (a password sealed on their device), then hand it back with the You chip. The agent reads but doesn't act meanwhile (open, act, login and call are refused), and a hold with no step for 10 minutes lapses. After the user signs in that way, the page offers to save the login.

New tab (in More, or in the tabs sheet) and the address pill show a new tab's home, under the same bar: its pill is one field for a search (through `SEARCH_URL`, else DuckDuckGo's plain HTML search) or an address, widening across the bar while it's typed in, with Clear and the You chip; suggestions rise above the bar while typing; Your sites lists the sites with a saved login first; Back is off, and More holds New tab and Logins. What the user opens there is a tab of their own, which the agent never reaches: it's named `you-<n>`, a name no chat's thread has, kept apart from the chats' tabs and in a browser context of its own (so its cookies aren't the chats', and its sign-ins end when the last of the user's own tabs or the browser closes; a login saved from it is in the Vault like any other), always held by the user, and nothing done in it is told to the agent. It goes through the fence as a chat's tab does: an address the fence refuses opens nothing, and the page says where to let it through.

A tab that closes, from its page or with its browser (after 20 minutes unused, or with AnythingLLM), keeps its page's frame: the same bar, the count holding the tabs still open and this one, and a new tab's home in the tab's place, with Back off. For two hours its page may open a tab of the user's own from there (the browser launched again if it closed; after a restart of AnythingLLM, once the agent has used the browser again), and nothing else; after that, or once its chat's thread opens a tab again, the page is gone and its link opens nothing.

Pages: fields inside open shadow roots work like any other. A password field stays one after "Show password" turns it into a text field, so `act` still won't type into it. A login isn't sent while its form still needs something else (a CAPTCHA, say): the agent and the user are told what. Fields inside iframes aren't read yet; there the user takes the tab over, and can't type into them either.

Passkeys: every tab has Chrome's virtual authenticator holding the saved passkeys, so a site's passkey sign-in works by itself. A passkey a site makes while the user holds the tab is offered for saving; one made while the agent has it is taken out again. The lean browser's passkeys are imported.
